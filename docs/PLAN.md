# LocalVoice: build and benchmark plan

This is the working plan for the project. It is written so an agent with no prior context
can pick it up. Read all of it before changing code. When you finish a task, tick it here
and add an entry to `docs/BUILD_LOG.md`.

---

## 1. Goal

Build **LocalVoice**, an offline hold-to-talk dictation app for Windows, similar to Wispr Flow.
You hold a key, speak, release, and the text is pasted into the focused window.
Speech recognition is NVIDIA Parakeet and runs locally.

**The build itself is documented as an engineering log** that proves two things with measurements:

1. **Comparison.** How LocalVoice stacks up against existing Windows dictation tools on transcription
   speed (release-to-text latency) and on CPU and RAM load.
2. **Hill-climb.** How one headline number, **CPU-seconds per minute of dictated audio (CPAM)**, was
   driven down one measured experiment at a time. Failed experiments are logged too.

Speed must never come from worse accuracy, so word error rate (WER) and latency are guardrails on every experiment.

## 3. Who can do what (important for agents)

Agents usually run in a **Linux cloud sandbox**. In past sessions that sandbox had:
- **no Windows**, so no keyboard hook, clipboard, Tk overlay or audio devices;
- **no access to huggingface.co** (blocked by the proxy), so models can't be downloaded;
- **no GPU**;
- no `tkinter` in the system Python.

So work splits like this:

| Agent (sandbox) | User (Windows PC with the GTX 1080) |
|---|---|
| Write and refactor code, unit tests (`pytest`), CI config | Run `scripts/install.ps1`, run the app, run `bench\run_bench.ps1` |
| Write the bench harness, analysis, chart generation | Install VB-CABLE, competitor apps, record own-voice clips |
| Turn the user's `bench/results/*.jsonl` into `experiments.tsv` rows, charts and log entries | Commit and push results, or paste them into chat |
| Propose the next experiment | Report anything odd (clipped words, focus stealing) |

**Never fabricate measurements.** Every number in the docs must trace back to a file in
`bench/results/`. If a number isn't measured yet, write `—` or `not measured`.

The GitHub Actions workflow (`.github/workflows/ci.yml`) runs tests on `windows-latest`, so
Windows-only code (Win32 structs, clipboard, hook, overlay) can be checked there without the user.
GitHub Actions may not be enabled on the repo yet. If no run appears after a push, tell the user.

## 6. Benchmark design

### 6.1 Metrics (exact definitions)

All times use `time.perf_counter()`. On Windows that is QueryPerformanceCounter, so readings
from different processes on the same machine can be compared directly.

| ID | Metric | Definition | Role |
|---|---|---|---|
| **CPAM** | CPU-seconds per audio-minute | Over one **session** (all clips, one pass): Σ over the app's process tree of Δ(user + kernel CPU time), ÷ (Σ clip durations in minutes). Process tree = root process(es) matched by name from the app profile, plus all descendants. Sample with `psutil` `cpu_times()` before and after. Processes that start mid-session are polled every 250 ms and their final CPU time is counted. | **Hill-climbed metric** (lower is better) |
| LAT | Release-to-text latency | `t_final − t_release`. `t_release` = harness timestamp just after the hotkey-up `SendInput`, or after starting dictation for toggle apps (see 6.4). `t_final` = time of the last text change in the target box, after which the text stayed unchanged for 1.5 s. Timeout 15 s, which counts as a failure. Report median (p50) and p95 over all clips × passes. | Guardrail + headline |
| TTFT | Time to first text | `t_first − t_release`. Can be negative for apps that stream text while you speak (Win+H). | Reported |
| WER | Word error rate | `jiwer.wer(normalize(ref), normalize(hyp))` over the concatenation of all clips in a pass (corpus-level WER, not the mean of per-clip WERs). | Guardrail |
| IDLE | Idle CPU | App started, 60 s settle, then 600 s with no interaction. Σ CPU seconds over the process tree ÷ 600 s × 100 = **"% of one core"**. Also record `num_ctx_switches` delta per second. | Headline |
| RSS | Memory | Process tree working set (`memory_info().rss`) and private bytes (`memory_full_info().uss`). Idle value = mean during the IDLE window. Peak = max during sessions (sampled every 250 ms). | Headline |
| VRAM | GPU memory | `nvidia-smi --query-compute-apps=pid,used_memory --format=csv` filtered to the app's PIDs. GPU utilization comes from `nvidia-smi --query-gpu=utilization.gpu --format=csv -lms 200` during sessions. | Reported |

**Text normalization for WER** (`bench/normalize.py`):
1. lowercase;
2. replace `-` and `/` with spaces;
3. remove every character that isn't a-z, 0-9, an apostrophe or whitespace;
4. collapse whitespace.

Numbers are **not** converted between digits and words. Note this as a known limitation.
Apply the same normalizer to every app.

**Cloud apps (Wispr Flow, Win+H):** CPAM counts local CPU only. Mark them with a † and footnote:
"compute runs on a server, so local CPU is not comparable".

### 6.2 Clip set (`bench/clips/`)

- **30 LibriSpeech test-clean utterances** (CC BY 4.0).
  - `bench/fetch_librispeech.py` downloads `https://www.openslr.org/resources/12/test-clean.tar.gz`
    and selects clips **deterministically**: sort all utterance IDs, keep those with duration
    3.0–20.0 s, shuffle with `random.Random(0)`, take the first 30.
  - Converts FLAC to 16-bit 16 kHz mono WAV.
  - Writes `bench/clips/manifest.jsonl`.
  - Commit the manifest; **don't commit the audio** (add it to `.gitignore`).
  - FLAC decoding needs `soundfile`, so add it to the `bench` extra.
- **10 own-voice dictation clips.** `bench/record_clip.py` shows each prompt below, records from

  1. "Hey Sam, can you send me the slides from yesterday's meeting before lunch?"

  4. "I think the second option is better, but we should check the cost first."
  5. "Remind me to call the dentist tomorrow morning at nine."
  6. "The build failed because the test for the parser timed out on Windows."
  7. "Thanks for the quick reply, that answers my question."
  8. "Can we move our one on one to next week? Something came up."
  9. "Add a note that the API key must never be committed to the repository."

### 6.3 End-to-end harness (works on any app)

Components:

1. **Virtual mic.** User installs [VB-Audio Virtual Cable](https://vb-audio.com/Cable/).
   Each app under test must have its microphone set to **"CABLE Output"**.
   The harness plays clips to **"CABLE Input"** with `sounddevice`, resampled to 48 kHz
   (resampling is done by the harness, not the driver).
2. **Target text box** (`bench/target.py`). A separate process runs a Tk window with one `Text`
   widget. On every content change it appends `{"t": perf_counter(), "text": <full text>}`
   to a JSONL file given on the command line. It has a "clear" command over a localhost socket or stdin.
   The harness focuses this window (`SetForegroundWindow` plus the Alt-tap trick if needed)
   before every clip and clears it in between.
3. **Driver** (`bench/harness.py`). For each pass and each clip:
   1. clear target, then focus target;
   2. wait 1.0 s;
   3. press the hotkey (`SendInput`);
   4. wait 300 ms (the **pre-roll**; the same for every app);
   5. play the clip to CABLE Input, blocking until done;
   6. wait 200 ms;
   7. release the hotkey and record `t_release`;
   8. wait until the text has been stable for 1.5 s, or the 15 s timeout;
   9. read the final text from the target log;
   10. wait 2.0 s gap.

   These timings are constants in `bench/harness.py` and must not change between runs.
4. **Resource sampler** (thread in harness). Every 250 ms it samples CPU times, RSS and USS of the
   app's process tree and appends to the results file. It also runs `nvidia-smi` sampling when present.
5. **Protocol for a run:**
   - Windows power plan "High performance" (or "Best performance");
   - close other apps;
   - laptop on AC power;
   - app started fresh;
   - **3 warm-up clips** (not recorded);
   - then **3 full passes** over all 40 clips;
   - then the IDLE measurement (600 s);
   - then the app is closed.

   One command: `bench\run_bench.ps1 -App localvoice -Label exp00`.

- the user physically holds the hotkey;

- `t_release` = the key-up timestamp the hook sees.

onnx-asr internals just for this split unless an experiment needs it.

### 6.6 Statistics and noise control

- Each run = 3 passes. CPAM is computed **per pass**. Report the median of 3 and the min/max.
- If (max − min) / median > 5%, the run is **noisy**: rerun it once. If it is still noisy, flag it in notes.
- Latency p50 and p95 are computed over all 120 clip-runs (40 clips × 3 passes). Timeouts are counted
  separately and excluded from the percentiles. More than 2 timeouts invalidates the run.
- Re-measure the current best config at the start of each benchmarking day. If it drifts more than 5%
  from its logged value, note the drift and re-baseline before accepting new experiments.

## 7. Hill-climbing protocol

- **Primary metric:** CPAM (lower is better).
- **Accept** an experiment only if **all** of these hold, compared with the current best:
  - CPAM improves by **≥ 3%** (median vs median);
  - LAT p50 is no more than **10% worse** (or no more than 20 ms worse, whichever is larger);
  - WER is no more than **0.3 points absolute** worse;
  - IDLE is no worse than +0.1% of a core.
- **One change per experiment.** If two changes are needed together, explain why in the hypothesis.
- **Every experiment gets a row**, accepted or not. Rejected experiments are reverted, but their code
  is kept on a branch `exp/NN-short-name` so they can be revisited.
- **Commits:**
  - accepted experiments land on the main working branch as one commit with message prefix `expNN: `;
  - the commit that adds the results row is `expNN results: ...`.
- Some experiments target **latency or idle CPU** rather than CPAM (E02, E07, E09). They are accepted
  under the same guardrails, with their own target metric improving ≥ 3% and CPAM no more than 3% worse.
  Mark the target metric in the row.

### `docs/experiments.tsv` columns (tab-separated, header row required)

```
id	date	commit	parent	change	hypothesis	target_metric	provider	cpam_med	cpam_min	cpam_max	lat_p50_ms	lat_p95_ms	ttft_p50_ms	wer_pct	idle_pct_core	rss_idle_mb	rss_peak_mb	vram_mb	timeouts	accepted	results_file	notes
```

### Phase 3: Hill-climb experiments

Run in this order unless results suggest otherwise. Each one needs a hypothesis written **before** measuring.

| ID | Change | Hypothesis / why | Target | Notes / how |
|---|---|---|---|---|
| E01 | `device: cuda` (fp32 on GTX 1080) | The encoder moves to the GPU, so CPU time per clip drops sharply | CPAM | Needs A1 true; else `directml`. Keep fp32: Pascal fp16 throughput is about 1/64 of fp32. |
| E02 | Overlay idle: stop the 30 ms `after()` loop while hidden; schedule ticks only while listening | Idle wakeups and idle CPU drop to about 0 | IDLE | `overlay.py:_tick`. Keep the level meter while listening. |
| E03 | ORT threads: `intra_op_num_threads` ∈ {1, 2, 4}, `inter_op_num_threads=1`, `session.intra_op.allow_spinning=0` | Spinning thread pools burn CPU after each call; with the encoder on GPU, few CPU threads are needed | CPAM | Pass `sess_options` to `onnx_asr.load_model`. Each thread count is a separate sub-run (E03a/b/c). Accept the best. |
| E04 | Preprocessing on GPU (`preprocessor_config={"use_numpy_preprocessors": False, "use_conv_preprocessors": True}`) vs numpy | Mel feature extraction leaves the CPU | CPAM | onnx-asr auto-enables Conv STFT on CUDA, so check what E01 already does first. If it is already on, record "no-op" and skip. |
| E05 | Trim leading/trailing silence (energy or Silero VAD) before ASR | Less audio to process, and the 300 ms pre-roll silence is removed | CPAM, LAT | Watch WER for clipped words. |
| E06 | Recorder: larger `blocksize` (e.g. 1600 samples = 100 ms) instead of 0 (driver default) | Fewer Python callbacks per second while recording | CPAM | Check it doesn't add latency at stop. |
| E07 | Process EcoQoS / below-normal priority when idle; normal while recording/transcribing | Lower idle cost and power | IDLE | `SetProcessInformation(ProcessPowerThrottling)`. |
| E08 | Lazy imports + `gc.freeze()` after load; drop numpy copies in the callback (preallocated ring buffer) | Smaller RSS, less GC work | RSS, CPAM | |
| E09 | Mic pre-warm: keep a stream open with a 300 ms ring buffer vs open per press | Fixes first-word clipping and stream-open latency, but the mic is always on (privacy indicator) and costs idle CPU | LAT, WER | **Trade-off experiment.** Report both sides; the user decides. ## 10. Rules for agents working on this repo

1. Read this file and `docs/BUILD_LOG.md` (if present) first.
2. Don't fabricate any measurement or app behaviour. If you can't run something, write the code,
   give the user the exact command, and stop.
3. Keep `pytest` green on Linux. Put Windows-only code behind `sys.platform == "win32"` and Windows-only
   tests in `tests/test_windows.py` (skipped elsewhere, run in CI).
4. Don't change harness constants (6.3) or acceptance rules (7) mid-campaign. If you must, start a new
   campaign, re-baseline E00 and the current best, and log why.
5. One experiment per commit. Never mix a bug fix into an experiment commit.
6. Don't put model names or version identifiers of AI assistants in commits or docs.
7. Prefer small, readable changes that match the existing code style (type hints, short docstrings, `log = logging.getLogger(__name__)`).
8. Don't push to `main` or open a PR unless the user asks. Work on `claude/windows-offline-dictation`.
